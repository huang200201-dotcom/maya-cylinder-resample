# 架构

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `core.py` | 不依赖 Maya 的拓扑分析、约束、采样、几何和面角 UV 生成 |
| `adapter.py` | Maya 场景快照、活对象解析、结果创建、材质与软硬边适配 |
| `mesh_command.py` | 可撤销的网格创建命令；按版本/内容隔离，保留旧命令支持 Undo |
| `ui.py` | 原生 Maya 控件、预览会话、用户确认、更新协调与模块重载 |
| `update_ui.py` | GitHub 检查/安装按钮、确认对话框与成功/失败重载协调 |
| `updater.py` | 标准库网络访问、Release 校验、安全解压、备份与文件切换 |
| `config.json` | 固定更新仓库；清单名与支持范围由更新器/发布清单管理，不存访问令牌 |
| `self_test.py` | Maya 内创建临时模型的兼容自检，不覆盖完整界面流程 |

核心只处理快照数据，不读取 Maya 全局场景。界面持有对象句柄和每个预览各自的原可见状态，避免改名、撤销及跨模型分析后恢复错对象。结果副本独立，不覆盖原网格。

## 更新流程

1. 用户检查更新，读取固定仓库最新正式 Release。
2. 验证标签、版本、受支持 Maya 版本及更新清单。
3. 用户确认后下载归档，验证大小、SHA-256 和文件摘要。
4. 在目标脚本目录附近暂存完整包，拒绝越界路径、非法文件和符号链接。
5. 备份旧安装，切换完整新安装；失败时回滚。
6. 关闭旧会话，重新导入模块并打开新版窗口；旧 MPxCommand 不被卸载。

更新器不操作网格或修改场景，界面负责在更新前处理预览。新旧 MPxCommand 使用隔离名称/路径，不直接重载已注册并可能被 Undo 引用的旧类。更新后旧快照不继续使用，必须重新分析。

## 发布清单

发布附件包括安装 ZIP、`update-manifest.json` 和 ZIP 的 `.sha256`。ZIP 顶层固定为 `CylinderResample/`，Maya 安装包中的 Python 包路径为 `scripts/cylinder_resample/`，源码仓库仍采用 `src/cylinder_resample/`。

```json
{
  "schema_version": 1,
  "version": "0.3.0",
  "maya_min": 2024,
  "maya_max": 2024,
  "archive": {
    "name": "CylinderResample_Maya2024_v0.3.0.zip",
    "size": 12345,
    "sha256": "64 位十六进制摘要"
  },
  "files": {
    "scripts/cylinder_resample/__init__.py": "64 位十六进制摘要"
  }
}
```

`files` 必须列出全部安装到包目录的 Python 文件和 `config.json`，而不只列出变更文件。清单独立于 ZIP，避免归档摘要自引用。当前 schema 不提供数字签名；发布账户与 GitHub HTTPS 是信任边界。

## 测试层次

- 纯核心测试：拓扑、分段分配、尺度、端盖、UV/硬边/材质约束。
- 模拟场景测试：会话、预览、改名、显示状态、Undo 后对象存活。
- 更新器测试：正式版本选择、下载校验、不安全归档、切换与失败回滚。
- Maya 内自检：原生 API 创建和写入临时网格；需要正常 Maya 环境。
- 人工端到端：实际窗口、Undo/Redo、连续升级和失败恢复；目前未完成实机验证。

CI 只运行前三层及发布包静态验证，不能把它的绿色状态理解成 Maya 实机通过。
